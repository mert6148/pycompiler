§Rust IDE and Rusty compiler

This guide describes how the project is organized, how Rusty source is compiled, and how to extend the language safely.

§Run and test

Install the Rust toolchain, then run the IDE from the project root:

cargo run

Open http://127.0.0.1:3030. On Windows, run.bat is an alternative launcher. The package.json scripts also provide npm start, npm test, npm run build, and npm run format:check.

Run the compiler and documentation tests with:

cargo test

Generate the API documentation with:

cargo doc --no-deps

Open target/doc/pycompiler/index.html to browse the generated Rust documentation. The crate-level page is sourced from this file, so the project overview is also available alongside the compiler API.

§Request-to-output flow

  1. The browser sends the editor contents as UTF-8 text to POST /api/run.
  2. main.rs validates the request body and calls compiler::compile_and_run.
  3. The lexer converts characters to tokens and records line/column positions.
  4. The parser validates statements and variable declarations, then emits stack-machine bytecode. Conditional and loop instructions use patched jump targets.
  5. The virtual machine executes the bytecode and collects print output. Arithmetic is checked, and execution stops after one million instructions.
  6. The server returns the output as plain text, or a diagnostic with HTTP 400.

The public compiler entry point and CompileError are documented in the generated API reference under the compiler module. Their implementation is in src/compiler.rs.

§Rusty language

Rusty is an integer-only teaching language. Statements end with semicolons; blocks use braces.

// Add the numbers from one through five.
let total = 0;
let index = 1;
while index <= 5 {
    total = total + index;
    index = index + 1;
}

if total == 15 {
    print total;
} else {
    print 0;
}

Supported statements:

let name = expression;
name = expression;
print expression;
if expression { statements } else { statements }
while expression { statements }

Variables must be declared before use. A variable declared inside a block is local to that block; assignments to variables declared by an outer block are allowed. Conditions treat zero as false and every nonzero integer as true. Comparisons evaluate to 1 or 0.

Operator precedence, from highest to lowest:

OperatorsMeaning
unary -Negation
*, /Multiplication, integer division
+, -Addition, subtraction
==, !=, <, <=, >, >=Integer comparisons

Parentheses can be used to group expressions. // starts a line comment.

§Compiler implementation notes

  • TokenKind and Token represent lexical units and their source positions.
  • lex scans digits, identifiers, keywords, punctuation, and comments.
  • Parser::statement handles declarations, assignments, printing, conditionals, loops, and scoped blocks.
  • Parser::expression uses precedence climbing and emits postfix operations.
  • Instruction is the compiler’s stack-machine bytecode.
  • execute maintains the operand stack and variable store, applies checked arithmetic, and interprets jump instructions.
  • The unit tests in compiler.rs cover precedence, scope, diagnostics, comparisons, control flow, and execution limits.

When adding an operator, update the token type and lexer, define its precedence and bytecode in the parser, implement its VM behavior, and add a focused test.
